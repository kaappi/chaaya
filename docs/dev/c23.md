# C23 standard

Chaaya targets **ISO C23** (`CMAKE_C_STANDARD 23` in `CMakeLists.txt`). C17
(ISO C17 / “C18”) added no language features beyond defect fixes to C11; Chaaya
treats C17 as the baseline “old C” and prefers C23 facilities when they simplify
or harden the implementation.

Requires **CMake 3.21+** and a C23-capable toolchain (e.g. Clang 18+, GCC 14+,
recent Apple Clang).

---

## Policy

When writing or refactoring C in this repo:

1. **Prefer C23** over C11/C17 patterns when the result is clearer or safer.
2. **Do not** introduce C23-only syntax without a concrete benefit — avoid
   novelty for its own sake.
3. **Do not** rely on compiler extensions when a C23 standard feature exists
   (e.g. use `typeof` instead of `__typeof__`, `unreachable()` instead of
   `__builtin_unreachable()` where portable).
4. New code should be valid **C23 with extensions off**
   (`CMAKE_C_EXTENSIONS OFF`).

See [AGENTS.md](../../AGENTS.md) for the agent-facing rule.

## Features new in C23 (not in C17)

Grouped by how useful they are for Chaaya today.

### High value — prefer when touching related code

| Feature | Header / form | Use in Chaaya |
|---------|---------------|---------------|
| **`typeof` / `typeof_unqual`** | keyword | Safer object-like macros (GC root stack, primitive helpers) without repeating types or using GCC `__typeof__`. |
| **`unreachable()`** | `<stddef.h>` | VM opcode dispatch defaults, parser “impossible branch” paths (`src/vm.c`, `src/reader.c`). |
| **`static_assert`** | keyword | Layout checks on `ChValue`, struct sizes, opcode tables — no `#include <assert.h>` for `_Static_assert`. |
| **`[[nodiscard]]`** | attribute | Functions whose result must not be ignored (`ch_read_file`, `ch_gc_push`, parse APIs). |
| **`[[maybe_unused]]`** | attribute | Parameters reserved for future use or callback signatures. |
| **`stdckdint.h`** | `<stdckdint.h>` | Checked `ckd_add` / `ckd_mul` / … in `src/bignum.c`, fixnum fast paths, index arithmetic. |
| **`stdbit.h`** | `<stdbit.h>` | Leading/trailing zero counts, popcount — IEEE float/rational bit twiddling in `src/prim_math.c`, `src/reader.c`. |
| **`#warning`** | preprocessor | Compile-time notices (optional features disabled, transitional shims). |
| **`#elifdef` / `#elifndef`** | preprocessor | Cleaner feature guards in headers (`CHAAYA_HAS_LINENOISE`, platform `#ifdef` chains). |
| **`__VA_OPT__`** | preprocessor | Variadic debug/logging macros without trailing-comma hacks. |

### Medium value — adopt when a task needs them

| Feature | Notes |
|---------|--------|
| **`constexpr`** | Compile-time constants for opcode tables, feature flags, static lookup tables (`src/features.c`, `include/chaaya/opcode.h`). |
| **`auto`** | Local type inference where the initializer makes the type obvious; avoid obscuring public APIs. |
| **`nullptr`** | New C code may use `nullptr` for pointer null; existing `NULL` is fine — do not mass-convert. |
| **`#embed`** | Embed small static blobs (bootstrap snippets, test fixtures, version strings) without code generation. Requires `__has_embed` guard if we ever need a fallback. |
| **`[[deprecated]]`** | Mark transitional APIs during refactors. |
| **`memset_explicit`** | `<string.h>` — zero sensitive buffers (future crypto/FFI paths). |
| **`true` / `false` keywords** | Optional in new code; `stdbool.h` / `#t`-style names in Scheme-facing code stay as-is. |
| **`thread_local` keyword** | Replaces `_Thread_local` if/when we add threads (deferred). |

### Lower priority / defer

| Feature | Why defer |
|---------|-----------|
| **`_BitInt(N)`** | Chaaya already has bignum; fixed `_BitInt` widths rarely beat `int64_t` / bignum for Scheme numbers. |
| **Decimal floating types** | Not relevant to the numeric tower MVP. |
| **`#include` … `import` (modules)** | Toolchain support still uneven; stick to headers. |
| **`[[unsequenced]]` / `[[reproducible]]`** | For pure numeric helpers only; easy to misuse across GC boundaries. |
| **Annex K bounds-checking** | `memset_s`, etc. — optional hardening later, not bootstrap-critical. |

## C17 baseline (what we are moving away from)

These remain valid but are no longer the *preferred* style for new code:

| C11/C17 habit | C23 preference |
|---------------|----------------|
| `_Static_assert(expr, msg)` | `static_assert(expr, msg)` or `static_assert(expr)` |
| `_Thread_local` | `thread_local` |
| `__typeof__(x)` (GCC) | `typeof(x)` |
| `__builtin_unreachable()` | `unreachable()` |
| Manual overflow checks | `ckd_*` from `<stdckdint.h>` when checking matters |
| `__attribute__((warn_unused_result))` | `[[nodiscard]]` |
| Ad-hoc “should never happen” returns | `unreachable()` after diagnostics |

## Examples (patterns to copy)

### Layout guard (`include/chaaya/value.h`)

```c
static_assert(sizeof(ChValue) == 8, "ChValue must stay 64-bit NaN-boxed");
```

### Checked arithmetic (`src/bignum.c`)

```c
#include <stdckdint.h>

bool overflow = ckd_add(&sum, a, b);
if (overflow) { /* promote to bignum or error */ }
```

### VM default case (`src/vm.c`)

```c
#include <stddef.h>

default:
    snprintf(vm->error, sizeof(vm->error), "invalid opcode %u", op);
    return CH_UNDEFINED;
    unreachable();
```

### Nodiscard on fallible APIs

```c
[[nodiscard]] char *ch_read_file(const char *path, size_t *len);
```

### Preprocessor warning

```c
#ifndef CHAAYA_HAS_LINENOISE
#warning "Building without linenoise; REPL will use plain fgets"
#endif
```

### `typeof` in a macro (GC-safe temporary)

```c
#define CH_GC_GUARD(gc, expr)                     \
    do {                                          \
        typeof(expr) _ch_tmp = (expr);            \
        ch_gc_push((gc), &_ch_tmp);               \
        /* ... */                                 \
        ch_gc_pop((gc));                          \
    } while (0)
```

## Toolchain notes

- **CI** (`.github/workflows/ci.yml`): Ubuntu and macOS latest images; verify
  C23 after compiler image upgrades.
- **`chaaya features`**: reports `"language": "C23"` (see `src/cli.c`).
- If a C23 feature fails on a platform, fix or guard with `#if __STDC_VERSION__ >= 202311L`
  and document the fallback in this file — do not silently lower the project standard.
